# 画面反应辅助选片

这是 `feature/speaker-subtitles` 分支的可选功能，用于补充字幕无法表达的动作、互动及画面看点。它分析完整画面，不要求框选人物；人物换位置或直播布局改变时，不按固定左右位置认定身份。

## 使用

1. 在 AI 设置中准备支持图片输入的视觉模型，并允许画面分析。仅配置文字模型或选择纯字幕分析时不能启用。
2. 导入视频时勾选“画面反应辅助选片”，选择最多 4、8 或 12 个复核区间，默认 8 个。填写人物名称和制作要求仍有助于选片。
3. 按原流程生成。进度会显示“扫描画面变化与声音线索”和“复核连续画面反应”。
4. 在“预览与编辑 → 画面反应与选片依据”查看当前切片范围内的观察说明、关键帧及观察限制，点击“查看原片”跳到对应位置。
5. 不认可的证据可以“忽略这条依据”，也可恢复。它影响本项目后续重新选片，不重做已有切片、不修改原素材，也不是训练模型。

## 如何帮助选片

本地 FFmpeg 以 CPU 低分辨率扫描全景变化，同时测量音量突增。字幕中的互动线索、画面变化和音量信号共同用于寻找值得复核的位置；候选覆盖不同时间区间，避免预算只用在开头。场景变化附近补充前后画面，再交给视觉模型观察连续变化。

视觉模型每次接收一个约 14 秒的区间，含最多 16 张按时间排序的全景图、附近真实字幕、音量线索和制作要求，返回可见事件、依据、不确定性及实际采样时间。事件必须引用至少两张提供过的画面，并且时间不能超出该区间。可以返回零条；没有证据时不强行认定笑点或人物情绪。

这些事件进入原有字幕选片、旧分步选片与评分的参考上下文；另在分析专用字幕中加入带时间的画面标记，让缺少台词的反应也有机会成为候选。画面路线同样接收这些证据。标记不会作为原对白烧录或写回用户 SRT。字幕边界精修若会删掉已经完整纳入候选的无台词画面事件，会保留原选段边界；这只是保护已有事件，不是完整的独立切片质量复审。

## 模型、用量与性能

- 初筛是本地 CPU 的画面差异和音量测量，不依赖 NVIDIA CUDA，也不新增模型权重。音量突增不等于笑声、尖叫或接唱；本版没有语义声音事件分类。
- 具体动作与互动理解使用现有视觉模型接口。配置云端时，会发送上述候选画面、附近字幕与制作要求，可能产生用量；配置本地兼容服务时由该服务处理。纯 CPU 本地视觉模型的推理速度取决于你准备的模型，本次没有基准结论。
- “复核预算”限制本功能复核的区间数，不是金额上限。现有规划、封面等其他调用单独计算；模型接口原有的兼容参数修正也可能产生额外请求。真实用量以当前服务商计费及项目用量记录为准。
- 本地扫描按 180 秒分段解码，单段内存有界；整片扫描耗时仍随长度增长。长视频只复核预算内的短区间，可能漏掉小动作、轻微表情或无声音、无字幕的画面梗，不承诺全片完整理解。

## 恢复与数据

完成的本地扫描和有效视觉响应按素材、模型、字幕、制作要求、预算及算法版本缓存。重试复用完成区间；模型、字幕或要求变化后会重新计算相关复核，不沿用旧响应。关闭画面分析许可后，不继续发送后续画面。项目停止或删除会遵循现有取消检查；正在进行的一次模型请求可能需要结束。

接口、模型或复核结果失败时，保留完成证据与缓存，并沿用原字幕选片；供应商超时等请求错误不会自动连续尝试剩余所有区间。没有可用视觉模型时明确显示状态，不自动切换供应商或下载模型。

项目的 `metadata/visual-reactions.json` 保存最近报告和忽略选择；`metadata/visual-reactions/` 保存分段扫描、响应及全景抽帧；`metadata/analysis-only/visual-reactions.srt` 仅供分析。缓存暂无自动清理，包含源画面及字幕，备份、迁移和清理时按项目私有数据处理。
