# AutoClip 人物切片增强分支

本分支由 [Gdrkun/autoclip](https://github.com/Gdrkun/autoclip/tree/feature/speaker-subtitles) 维护，基于 [zhouxiaoka/autoclip](https://github.com/zhouxiaoka/autoclip) 二次开发，重点面向双人对话、直播人物互动、唱歌和玩梗切片。保留上游来源、贡献者说明及 [MIT 许可证](../LICENSE)。

当前功能位于 `feature/speaker-subtitles` 源码分支。README 中原有的官网、下载、案例、徽章与正式版更新日志属于上游；上游安装包不包含本分支新增功能。本分支尚未完成独立桌面安装包与双平台验收。

## 新增功能与入口

| 功能 | 使用入口与行为 | 详细说明 |
| --- | --- | --- |
| 说话人识别与双色字幕 | 设置中启用本地说话人字幕；CAM++ 提取声纹并聚类，Whisper / SenseVoice 识别文字；编辑页确认人物名称与颜色 | [说话人字幕](SPEAKER_SUBTITLES_INTEGRATION.md) |
| 字幕校对与样式 | 按当前切片展示字幕，支持补句、排序、归属纠正、字号、位置和描边；预览、ASS 与重新导出的 MP4 采用草稿设置 | [字幕布局与补句](SPEAKER_SUBTITLES_INTEGRATION.md#字幕布局与补句顺序) |
| AI 选片偏好 | 导入页组合唱歌、搞笑、流行梗、迷因等偏好，并补充具体制作要求；要求进入实际选段和评分提示 | [选片偏好](SELECTION_PREFERENCES.md) |
| 人物背景与手工知识 | 填人物名称，查询公开背景，保存人物档案、别名、梗的语境和字幕易错词 | [人物知识库](CREATOR_KNOWLEDGE.md) |
| 参考切片学习 | 从认可的 B站切片或 SRT 提炼人物梗、互动及选片经验；带来源、原话和时间，人工确认后参与未来选片 | [参考学习与恢复](CREATOR_KNOWLEDGE.md#从参考切片积累人物知识) |
| 选片反馈记忆 | 成片标记“多选这种 / 少选这种”，保留分类、原因和当前草稿范围内字幕摘录，供后续选片参考 | [反馈记忆](CREATOR_KNOWLEDGE.md#选片反馈记忆) |
| 歌声检测与长视频恢复 | 可选本地 CPU AST 歌声检测；说话人字幕和歌声按段处理、缓存并支持暂停后重试 | [歌声检测](CREATOR_KNOWLEDGE.md#本地-cpu-歌声检测) |
| FLV 导入和临时目录 | 导入 FLV 后可生成浏览器兼容预览；临时工作目录可在设置中指定 | [FLV](SPEAKER_SUBTITLES_INTEGRATION.md#flv-本地导入) · [临时目录](TEMPORARY_STORAGE.md) |

原有高光分析、剪辑与导出继续使用原链路；新增行为由对应设置及数据启用。人物资料和模型输出都需结合原视频核对。

## 获取与准备

新克隆时明确指定个人 fork 的功能分支：

```bash
git clone --branch feature/speaker-subtitles https://github.com/Gdrkun/autoclip.git
cd autoclip
```

已有工作副本先保存自己的改动并备份数据，再切换或更新分支；不要直接覆盖已有 `.env`、模型、项目和草稿。

- 基础服务按 [源码启动指南](../STARTUP_GUIDE.md) 准备 Python 虚拟环境、Node.js、FFmpeg/FFprobe、Redis 和 Celery。该指南的启动脚本面向 macOS/Linux，Windows 使用对应手动命令；本分支当前开发验证使用 Windows、Python 3.12 和 CPU。
- 前端通过 Vite 代理访问后端；修改端口时同时配置 `BACKEND_URL` 和后端 `AUTOCLIP_ALLOWED_ORIGINS`，两者作用不同，见 [接入说明](SPEAKER_SUBTITLES_INTEGRATION.md#使用)。API 与 Worker 应使用相同的数据目录、数据库、模型配置和运行时路径。
- 说话人推理使用独立可选环境，依赖见 [requirements-speaker.txt](../requirements-speaker.txt)，不要装进 FastAPI 的基础环境。默认运行时为数据目录下的 `speaker-runtime`，可通过 `AUTOCLIP_SPEAKER_RUNTIME` 指定；其中需要 `venv` 以及 `models/campplus`、`models/fsmn-vad` 和所选的 `models/whisper-medium` 或 `models/sensevoice`。Whisper 使用 CPU int8，不依赖 NVIDIA CUDA。
- Git 仓库不包含模型权重或个人运行配置。新克隆不代表模型已准备好；先在转写设置检查所选模型就绪状态。识别阶段只读取本地模型，不隐式下载或调用付费 ASR。
- 高光分析和参考知识提炼使用你配置的文字模型。本地模型需先启动兼容服务；使用云端文字模型时会发送相关字幕和资料，并可能计费。

## 日常使用流程

### 自动生成与校对人物字幕

1. 在“设置 → AI 模型 → 字幕转写”选择本地 Whisper 或 SenseVoice，打开“说话人字幕”，确认模型就绪并保存。
2. 导入视频，填写人物名称、选片偏好和制作要求，按原流程生成切片。已有字幕会尽量复用；仅有 SRT 通常没有说话人归属，仍需从音频提取声纹。
3. 自动制作会在需要时补齐说话人信息；预览与编辑按当前切片范围显示字幕。旧草稿允许自动字幕且缺少结果时也会补齐，失败可重试。
4. 确认匿名人物编号对应谁，调整名称、颜色、文本、时间、样式和重叠行，保存草稿。切换切片时展示各自范围与校对快照。
5. 下载 ASS 或重新导出 MP4。保存草稿不会覆盖已经生成的视频，已有 MP4 需要重新导出才包含新修改。

### 让人物知识参与未来选片

1. 导入页打开“人物知识库 → 参考切片学习”，填写人物名称；多人用顿号分隔。
2. 每行粘贴一条 B站视频完整 HTTPS 链接，一次最多 10 条。短链先在浏览器打开后复制完整链接。也可提供 UTF-8 SRT 与认可理由；附 SRT 时一次只加一个样本。
3. 优先读取平台字幕。没有可用字幕时，可选已经准备好的本地 Whisper / SenseVoice CPU 转写，或直接提供 SRT。
4. 点击“分析并生成待确认条目”，核对来源、原话、时间、适用语境和误读提醒，再“确认并启用”。待确认或停用条目不参与自动选片。
5. 后续导入填写相同人物名称或档案别名。系统按人物和当前真实字幕检索相关条目，并将它们提供给选片 AI。当前制作要求优先于历史经验。
6. 在成片上继续反馈“多选这种 / 少选这种”，修订不准确的条目，逐步积累可复用的选片依据。

这里的“学习”是保存、检索知识并加入模型上下文，不是训练或微调模型。编辑页的参考面板读取项目最近一次提供的知识回执，不是逐草稿历史，也不能证明模型逐条采用了知识。

## 数据与费用

- 旧角色档案、字幕词库和反馈位于数据目录的 `creator-library.json`；新参考知识、备份和任务缓存位于 `creator-learning/`。项目原片、SRT、说话人结果和草稿仍按原项目结构保存。
- 知识确认和停用立即保存；角色档案、词库等手工编辑仍使用“保存知识库”。知识修订采用版本校验，冲突时刷新核对，不以旧页面覆盖新数据。
- 备份时包含整个数据目录和模型配置；只迁移临时目录不会迁移原片、成片、模型或知识库。参考任务缓存暂不自动清理，长视频和模型会占用磁盘空间。
- 参考学习只在点击分析后启动，不自动抓取整个账号或评论。平台读取需要网络；本地 ASR 不上传音频给云端，但配置为云端的文字分析仍会发送字幕、标题、简介、人物范围和备注。

## 当前限制与验证范围

- 当前主要面向匿名双人声纹聚类；CAM++ 不识别真实姓名，人物绑定需人工确认。歌声、相近音色和多人同时发言仍可能漏识别或分错。
- 支持手工补充和渲染重叠双行，尚未做两路人声源分离，不能保证同时发言都被自动转写。说话人字幕使用原语言，不自动翻译。
- AutoClip 集成入口已支持按段处理长视频；独立 `scripts/speaker_poc.py` 仍是最多十分钟的原型。CPU 转写耗时与素材长度相关，参考学习也建议先选短切片或提供 SRT。
- 初版参考学习依据字幕和备注，不自动理解纯画面梗，不根据单次互动认定长期人设。知识提炼及选片效果取决于素材、转写、文字模型和人工确认。
- ASS 保存颜色、字号、位置和描边；剪映、必剪导入后不保证保留样式。尚未提供剪映或必剪原生工程导出。要固定视觉效果可导出烧录字幕的 MP4。
- 本次参考学习相关后端 96 项（其中功能专项 25 项）通过；前端 lint、类型、324 项测试和构建通过；contracts 83 项通过。界面和选片协议使用隔离模拟；真实 B站短片完成本地 CPU 转写，但未验收真实文字模型提炼或选片质量。
- 最近全量后端结果为 2327 通过、25 失败、7 跳过、2 错误，包含既有 Windows/环境问题及 Sentry 线程等待失败；该 Sentry 用例在当前与未修改基线独立复验均通过。全量门禁仍未通过，不代表发布或双平台安装包验收通过。
