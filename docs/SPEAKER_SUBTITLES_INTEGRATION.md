# AutoClip 本地 Whisper 与说话人字幕接入

日期：2026-10-14；分支 `feature/speaker-subtitles`。此次接入现有设置、转写入口、Studio 草稿及导出，不新增独立试测页面。

## 使用

1. 在当前开发版网页打开“设置 → AI 模型 → 字幕转写”，选择“Whisper · 本地”，开启“说话人字幕”。本地模型已准备时显示 Whisper medium / CPU int8；可填写人名、固定用语提示，再保存设置。现有分析模型和密钥保持原配置，原高光分析仍遵循其供应商配置。
2. 正常导入无字幕视频时，原 `generate_subtitle_for_video` 入口会使用独立 CPU worker 转写与提取声纹，保存原片时间轴 SRT 和项目 speaker sidecar。新草稿自动继承 speaker 数据。
3. 已有项目在 Studio 打开“说话人字幕”，选择模型并识别。需要重新转写文字时取消“复用已有字幕”；有校对好的原片 SRT 时保留该选项。后台完成后可“应用识别结果”，然后确认匿名 speaker 对应的人物。
4. 编辑人物名称和颜色、逐句文本/起止/归属，必要时补充第二行；保存草稿后可下载 ASS，或使用原“导出成片”生成双色 MP4。刷新后保留编辑内容，旧成片不被覆盖。

本机正常开发页面改用 `http://127.0.0.1:13001/`，连接原 `18765` API；`3000/3001` 已由其他项目占用，未改变那些服务。独立验收页面/数据库仅用于测试，不是正常开发数据。API/Worker 依然使用原开发配置和 Redis。

使用上述 `13001` 前端端口时，必须在启动后端的同一 PowerShell 会话追加来源白名单，再运行原 uvicorn 启动命令（若后端已运行，需要重启）：

```powershell
$speakerDevOrigins = @($env:AUTOCLIP_ALLOWED_ORIGINS -split ',' | Where-Object { $_ }) + @('http://127.0.0.1:13001', 'http://localhost:13001')
$env:AUTOCLIP_ALLOWED_ORIGINS = ($speakerDevOrigins | Select-Object -Unique) -join ','
```

Vite 代理的 `changeOrigin: true` 会把请求 Host 改成后端地址，浏览器 Origin 仍是 `13001`；默认来源仅包含开发端口 `3000`，漏配会令模型列表刷新、保存设置和 Studio 写请求返回 `403 origin_not_allowed`。仅追加当前本机前端来源，保留其他已配置来源，不关闭来源守卫或修改现有 `.env`。2026-10-14 已验证本机两种来源能通过，其他网页来源仍被拒绝。

## 接入与兼容

- `ai_model_settings.Transcription` 增加可选 speaker 开关与 prompt，默认关闭/为空且默认值不增加旧序列化字段。云端和未开启功能的旧转写分支保持原行为。
- `speaker_integration.py` 在 API/Worker 进程中只负责配置、文件和子进程；模型在独立环境运行，推理阻断网络，不调用付费 ASR/LLM。Whisper 本地目录、CPU、int8、关闭远程模型下载；CAM++/SenseVoice 继续可选。
- Whisper 根据真实词时间戳、说话人切换及字幕长度拆句，不把一个长 segment 强贴成单个 speaker；旧 SRT 可复用。不将词语提示当作自动纠错事实。
- 项目 `metadata/speaker_subtitles.json` 保存源片相对时间；Studio Draft 保存可编辑快照，受原草稿 revision/冲突机制保护。识别失败、中断时保留旧结果，损坏的 sidecar 不阻断旧字幕模式；不做数据库迁移。
- `studio.store/jobs` 为新生成/导出的草稿继承 source sidecar；`studio.render` 在已开启的数据分支生成按 scene 裁切、重排映射的 ASS，保持原音轨/画幅/剪辑时间轴。颜色关闭时继续使用已校对文本，统一白色；没有 speaker 数据时走原渲染。
- 颜色通过 ASS BGR 编码，重叠 cue 自动分配上下两行，人工指定 layer 可以保留。此模式使用普通字幕样式和既有标题路径，替代包装模板的字幕层，避免重复字幕；未开启的数据保持原包装路径。
- 新路由使用原 Studio 项目校验和来源守卫：模型状态、项目识别任务/结果、草稿 ASS 下载。只改字幕或颜色不会重新执行高光分析或翻译 LLM。
- 设置及 Studio 新文案覆盖现有八种语言。质量 runner 在 Windows 通过 npm.cmd 执行前端门禁，避免找不到 npm。

## 字幕布局与补句顺序

Studio“说话人字幕”增加字号缩放（50–250%）、横向位置（画面宽度 5–95%）、纵向位置（画面高度 15–95%）和“恢复字幕布局”。位置表示下行字幕的底部中心，上行按字号自动保持间距；数字越大越靠右/靠下。布局跟随草稿保存、复制及导出，不重新分析高光或转写。原草稿没有 layout 字段时继续使用此前 ASS 的默认布局；已有 JSON 默认序列化形状不变。

“补充字幕”按当前播放位置插入时间序列；每行可以“在此后补句”，或用“上移/下移”调整列表，也可以“按时间排序”。列表排序保留字幕 ID、文本、归属和起止时间；视频中播放顺序始终按起止时间，修改时间后可以再排序。同起点/字幕行保持列表顺序，重叠两行在实时预览和 ASS 使用同一分配规则；上行/下行仍可手工选择。补句默认下行，重叠时自动分配可用行。

实时原片预览、下载 ASS 和 MP4 均采用草稿布局；ASS 使用实际输出画幅，关闭颜色时下载 ASS 也保持白色校对字幕。长文本换行和字体度量以渲染结果为准。

2026-10-14 验证：新增/既有 speaker 定向后端共 70 passed，无 skip，覆盖参数边界、旧序列化、HTTP 保存/刷新、手工顺序、实际画幅 ASS、颜色关闭及真实 FFmpeg 像素大小/位置对照与全解码；前端完整 lint/types/298 tests/build 通过，八语文案一致。Edge 隔离合成项目实际设字号 150%、位置 40%/60%，行后补句、上移及时间排序，保存刷新、实时预览和 ASS 参数均保持；从原导出弹窗生成 6s MP4，音视频轨及全解码通过，抽帧确认补句在设置位置。没有模型/付费调用或修改用户项目。完整 backend、桌面安装包及双平台验收未完成，仍不是发布验收通过。

## 长视频与分段恢复（2026-10-15）

AutoClip 的说话人字幕集成入口已取消原型的 10 分钟整片限制。超过 10 分钟的视频按 180 秒核心区间、左右各 4 秒重叠读取；单个模型子进程最多处理 188 秒音频，继续使用本地 CPU。短视频保留原有 POC 路线，独立 `scripts/speaker_poc.py` 本身仍是十分钟原型；长视频请从 AutoClip 界面使用。

每段保存校验后的字幕与 CAM++ 声纹。全片完成后，对均匀采样的最多 256 个声纹建立全局聚类中心，再为所有窗口统一匹配人物编号；同一人在下一段先开口不会简单变成另一个人。编号仍是匿名编号，不代表真实身份，声音变化或唱歌可能影响准确率，需人工校对。当前上限仍为两位说话人，不进行重叠语音源分离。

模型读取的局部时间转换为原视频时间，重叠区按核心区间归属，移除重复字幕。已有 SRT 复用时保留原字幕文字、时间和重叠行。结果只有在全部分段成功、全片 schema 校验后才写入，失败不替换原有字幕。

项目 `metadata/audio-chunks/speaker/<identity>/` 保存分段缓存和进度。身份包含源视频位置、大小/修改时间、模型文件、提示词、原字幕及相关算法文件；相同输入重试复用已完成分段，变更输入或模型后使用新缓存。损坏、不完整或超出局部时间的缓存会重跑。跨进程锁避免同一素材配置并发写入。

字幕面板显示分段进度并提供“暂停识别”；自动制作的运行状态提供“暂停处理”。暂停会终止本地子进程，保留完成分段和已有草稿，重试继续；排队任务的暂停也有独立回执。每个分段设置独立超时，不再用一个固定总超时覆盖整个长视频。缓存暂不自动清理，保存在本机，不上传音频或声纹。

本次确认用户 2 小时 25 分 16 秒视频可通过检查，将拆成 49 段；实际 CPU 验证使用其前 10 分 20 秒素材，完成四段 SenseVoiceSmall+CAM++ 并输出全局两人字幕。再次运行全量复用缓存且结果一致。不是全片转写或识别准确率验收；完整原片未在本次自动测试中跑完。

## 2026-10-16 避免重复字幕与说话人字幕的优先级

草稿已有可用的说话人字幕时，原片自带字幕的检测结果不再直接关闭说话人字幕。生成平台版本时先继承已有识别结果，保留人物名称、颜色、逐句校对和重叠信息，不再为替代字幕调用模板字幕生成。已知原片字幕区域时复用该区域做局部模糊，再叠加说话人字幕；原片预览和实际导出都显示这层遮挡。未定位字幕区域时不猜测遮挡范围，保留说话人字幕，并提示可能重叠。

自动避重复关闭使用可选 `subtitles_auto_suppressed` 标记，默认不增加旧草稿字段。用户手动关闭字幕时清除该标记，之后保存、重开、导出均保留关闭选择；关闭说话人字幕时不模糊原字幕区域。应用一次识别结果会开启字幕并使用现有遮挡区域，编辑文字或人物本身不擅自更改用户的显示开关。

旧版本中，仅对已保存说话人字幕、原片判定自带字幕、第一版且来源为自动生成、未关闭人物颜色的草稿恢复自动误关。恢复前保存完整 Studio JSON 备份，恢复后增加草稿 revision，使旧视频保持原文件和原版本，新导出使用修复后的版本；备份或保存失败时保留原草稿。已人工保存过的旧草稿、手动创建、无说话人数据的草稿不据此自动改动。编辑期间刚完成识别的 sidecar 不触发这种旧稿迁移，避免改变正在编辑的 revision。

该修复不重新识别语音、不重新分析高光，也不会自动重做已有 MP4。旧成片需要从修复后的草稿重新导出一次；已有视频、字幕校对和原导出记录保留。

恢复不会覆盖旧版本浏览器暂存；编辑器保留暂存并可“恢复暂存为新版本”。复制出的版本不按初始自动草稿迁移，手动关闭字幕的选择保留。


## 2026-10-16 制作前自动补齐与切片范围校对

开启“说话人字幕”时，内容/视觉草稿制作前检查该原视频项目的说话人结果。已有有效结果直接复用；已有原片 SRT 或 metadata 转写缓存但缺少说话人数据时，只运行本地 CAM++/VAD 并按原字幕时间关联，不重新转写，不改写原 SRT。本地转写模式尚无 SRT 时先生成文字与说话人结果，再开始选片；云端模式的文字调用仍由原转写路线控制，本补齐步骤不会新增云端调用。开关关闭、无音轨或只有分析用歌声标签时保留原流程。模型缺失或识别失败会明确失败，保留字幕和草稿，避免生成看似成功却缺少人物归属的结果。

普通字幕流水线在选片前同样补齐；metadata 中的已有转写会复用。识别进度可见，同一原视频的自动请求通过文件锁串行去重；API 与 worker 使用进程创建时间确认任务归属，避免把另一进程的活跃任务误判为中断。提供 SRT 时只要求 CAM++/VAD 公共组件，无需额外安装未使用的 ASR 模型。长片继续复用已有分段缓存，手动重新识别仍可显式更新项目源结果。

校对面板只显示与当前草稿任一镜头相交的字幕，时间仍使用原视频时间轴。两段切片的人物编号与默认颜色可复用，但文字校对快照分别保存；后台源识别和其他草稿不会被当前草稿的校对覆盖。试听会跳到正确镜头，并将跨切点字幕的起点限制在镜头内；原片预览和已渲染预览切换均处理。排序、移动、补句和词库纠错只作用于当前范围内的条目，范围外字幕仍保存在快照中，不做破坏性裁切。多镜头草稿允许试听跳转到对应镜头，同一原片片段重复使用时保留原时轴语义。

旧项目的编辑器在草稿缺少说话人结果且允许自动字幕时，通过 `POST /api/v1/studio/{project_id}/speaker-subtitles/ensure` 排队补齐；GET 仍只读取状态。全局开关关闭、手动关闭字幕或人物颜色、已暂停的任务不会自动重启。已有有效项目结果直接应用到当前缺失结果的草稿，不覆盖已经保存的校对。后台任务失败保留具体错误和原字幕，用户可以显式重试。成功应用后保存草稿，已有 MP4 需重新导出才会包含本次字幕；不会在后台覆盖旧成片。
