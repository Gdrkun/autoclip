# 角色档案管理

在导入页打开“人物知识库”。查询完成后也可从“保存到角色档案”进入；查询结果与正式档案分开，查询成功不等于已保存。

## 管理与保存

- 左侧按名称、别名搜索，可按最近修改或名称排序；右侧集中编辑角色名称、别名、背景、人物关系、梗和参考来源。
- 未保存的档案有单独标记。底部固定显示未保存、保存中、保存成功或失败，成功后显示本机保存时间。保存失败保留编辑内容，可原地重试。
- 别名、易错词随输入更新，不依赖离开输入框后再提交。重复名称、别名和无效词条会阻止保存并给出原因。
- 关闭有修改的窗口时，可保存并关闭、保留草稿后关闭或继续编辑。浏览器本机草稿不等于正式档案，刷新后可明确选择恢复；存储不可用时会提示先保存。
- 删除需要确认，保存前可从“待删除档案”撤销。正式修改仍保留上一版 `creator-library.backup.json`，损坏原文件不会被空白知识库覆盖。
- 已保存且无未保存改动时，可点击“用于本次制作”，填入角色查询框，后续制作按名称匹配其档案。

## 查询结果导入

点击“预览导入”查看准确的目标角色和将写入的背景，确认后先加入编辑草稿，再保存。

同名或同别名档案保留原有人工背景与梗，仅追加新 URL 的资料。最多保留 8 条参考来源，背景最多 6000 字；导入预览展示这些约束下的实际内容。不会因为重新查询而直接替换人工校对。

## 多页面修改

保存按编辑前基线、当前草稿和最新已保存版本逐字段比较：

- 不同档案、不同字段的修改自动合并；后台新增的选片记忆不会被旧编辑页整库覆盖。
- 同一字段两边都改动，或一边删除而另一边编辑时，返回 409 并保留双方内容。界面对照展示，可逐项选择保留本地或使用已保存内容；合并到草稿后仍需检查并保存。
- 字幕词库作为一个有顺序的列表处理。两边同时修改词库时需要显式选择，避免推测词条身份。
- 不同编辑页使用独立的本机草稿键。恢复另一页旧草稿后，保存不会删除该页后来继续编辑的新草稿。

## 接口

- `GET /api/v1/studio/creator-library`：读取本机已保存知识库。
- `POST /api/v1/studio/creator-library/changes`：提交 `{base: Library, draft: Library}`，原子应用可合并更改，返回实际已保存的 `Library`。冲突返回 `{detail:{code:"creator_library_conflict",current:Library,conflicts:[{section,id,field}]}}`。
- 原 `PUT /api/v1/studio/creator-library` 保留全库版本检查，旧客户端可继续使用。新界面采用上述合并接口。
- `updated_at` 为可选新增元数据；旧知识库可直接读取，服务端在实际保存时维护知识库和被修改档案的时间，不信任客户端填写的保存时间。

管理操作仅保存到本机，后续转写和选片仍按已有上下文策略使用这些资料。主动查询背景仍使用原有公开查询流程；本次管理改动没有增加外部服务调用、数据库表或依赖。
