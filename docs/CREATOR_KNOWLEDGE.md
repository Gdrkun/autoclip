# 人物知识库、参考切片学习、字幕词库与选片记忆

## 角色档案与梗词典

导入页点击“人物知识库”。可以新建角色，填写准确名称、别名、人物背景与关系、梗的含义和适用语境。查询背景后，也可以点击“保存到角色档案”，从检索结果分别新建档案并修订。已有同名档案保留人工修订，不会被网页查询覆盖。

保存后，在导入页“角色或组合名”填写对应名称或别名，程序会匹配档案。多个名字用顿号或逗号分隔，平台与所属组合放在括号内。例如：`思诺snow、心宜不是心仪（B站/枝江娱乐）`。人物设定是理解视频的参考，不能证明视频里发生了某个事件。

## 字幕词库

知识库的“字幕词库”支持正确写法、多个易错写法和适用角色。角色留空表示通用；例如正确写法填“心宜”，易错写法填“心仪、新宜”。不建议把容易歧义的短词写成通用替换。

- 正确写法及匹配的角色名称作为热词传给本地 Whisper，包括普通转写和说话人字幕转写；保留手动提示词，总长度限制 500 字。词库只是识别提示，不保证识别结果。
- 在草稿编辑的“说话人字幕 → 词库纠错”点击“检查易错词”，核对并勾选建议，再点击“应用选中的纠错”和“保存草稿”。SenseVoice 使用此识别后纠错流程。
- 仅修改字幕正文，保留时间、说话人、颜色和上下层。扫描后手动改过的正文不会被旧建议覆盖；相互冲突的替换不会猜测选择。不会自动修改旧字幕文件。

## 选片反馈记忆

在成片草稿或自动成片卡片下点击“多选这种 / 少选这种”，选择唱歌、搞笑、人物互动、玩梗或其他，并补充具体原因。反馈保存在本机；有角色的反馈仅匹配这些角色，无角色的反馈为通用偏好。相同草稿重复反馈会更新原记录。

后续选片模型会接收分类、备注、示例标题及该草稿镜头范围内的字幕摘录，不是只匹配标题文字。优先保留近期反馈，新的反馈会替换同一草稿的旧选择。当前明确填写的制作要求优先于历史反馈。知识库“选片记忆”可以查看记录，点击“忘记这条”后保存知识库即可移除。原有下载后的成片可用性评分仍用于原统计流程，与本地选片记忆分开。

## 从参考切片积累人物知识

在“人物知识库 → 参考切片学习”填写人物名称（多人用顿号分隔），粘贴认可的 B站视频完整链接，每行一条，一次最多 10 条。分享链接的跟踪参数会去除，分P参数保留。当前不接受空间主页、播放列表或短链接；短链接可以先在浏览器打开，再复制视频完整链接。

可以展开“提供字幕或补充说明”，附上 UTF-8 SRT、参考标题及“你认可它的原因”。附带 SRT 时一次只添加一个样本，避免将同一份字幕错误关联到多条视频；也可以只提供 SRT，保留为用户提供的参考证据。

点击“分析并生成待确认条目”才开始任务。优先读取平台字幕；无可用字幕且勾选本地转写时，下载低分辨率参考素材，使用已准备好的 Whisper medium 或 SenseVoiceSmall 本地 CPU 运行时生成带时间戳字幕，不自动下载模型，不回退云端转写。文字分析使用当前配置的文字模型，会发送参考字幕、来源标题/简介、人物范围及备注，可能产生该模型的用量。不会自动爬取整个账号、抓取评论或把参考视频上传给文字模型。

模型将样本提炼为“人物梗、选片经验、人物互动、专有名词”。每条记录说明、触发词、适用语境、误读提醒、来源链接、参考字幕原话和参考片段时间。引用的字幕 ID、连续区间和原话必须与输入一致；模型不能自行改人物范围、伪造来源或把条目直接设为已确认。没有证据时可以返回零条，不把标题、播放量或单次互动当作长期人设。

初版主要根据字幕和备注学习，不会从字幕中声称看到了表情、动作或听到了笑声。纯画面梗需要人工补充和核对；自动提炼的解释也需要确认，不保证真实梗含义和来源都正确。

新条目默认“待确认”，不会进入自动选片。核对原话、来源及语境后，可以修改条目并点击“确认并启用”；之后可再次编辑或停用。确认与停用立即保存到独立知识库，不覆盖旧角色档案、字幕词库或手工填写的梗。条目修订号防止其他页面的旧数据覆盖新修改，原始证据不能通过编辑接口改写。

后续制作时，仍需在导入页“角色或组合名”填写相应人物或别名。系统按人物隔离，只检索已确认条目，再根据当前真实字幕中的触发词和相关内容排序，最多选取 8 条并限制上下文长度；通用选片经验可以作为模式参考，具体梗、关系和名词需有当前字幕线索。快速选片直接使用实际送入模型的字幕，兼容字幕在项目目录外的调用；旧版选段及评分同样接收人物知识。知识和反馈改变后，相关选片缓存随上下文变化，不自动重做旧项目。

草稿编辑页的“本次选片参考的人物知识”展示实际提供过的条目和来源。它表示已提供参考，不表示模型逐条命中或认可了全部内容；提示词要求只有当前素材确实匹配时，才在推荐理由中说明条目名称和当前依据。参考片段的时间不得当作当前原视频的时间。

## 参考学习任务与恢复

任务显示读取、下载、本地转写及知识提炼进度。重复提交相同参数的排队、运行或完成任务会复用结果。分段文字分析每段控制输入量，保留相邻语境；完成的转写及有效分段结果保存在本机。失败后点击“重试”，复用已完成工作。GET 只读取状态，不启动分析；服务重启后中断的任务会明确失败，需手动重试。

“停止后续分析”防止继续调用模型或将未完成结果写入知识库；正在进行的下载、转写或单次模型请求可能仍需结束，已完成转写保留。停止不删除已有条目。样本及缓存暂不自动清理。

学习数据位于当前数据目录的 `creator-learning/`：`knowledge.json` 保存独立条目与修订号，`knowledge.backup.json` 保留上次状态，`jobs/<id>/` 保存参数、任务状态、来源转写及分段分析缓存。使用线程锁和文件锁避免并发写入；损坏知识库保留原件，不覆盖为空库。最多保存 5000 条条目。项目的 `metadata/creator-knowledge-context.json` 保存项目最近一次提供给模型的参考条目，不是逐草稿历史，也不是逐条实际命中证明。旧 `creator-library.json` 格式兼容，旧反馈无字幕摘录时仍正常使用。

## 本地 CPU 歌声检测

导入页可勾选“检测歌声，辅助完整保留演唱片段”。首次使用需要现有本地说话人运行时，并下载约 330 MiB 的免费模型。默认关闭，不会自动下载；新环境需自行准备。

使用官方 [MIT AST AudioSet 模型](https://huggingface.co/MIT/ast-finetuned-audioset-10-10-0.4593)，权重固定为 `f826b80d28226b62986cc218e5cec390b1096902`，使用 safetensors；Torch 在隔离子进程以 CPU 推理，不依赖 NVIDIA CUDA，不导入 FastAPI 进程，不改共享 Python 依赖。

模型按 10 秒窗口、5 秒步长识别歌唱、哼唱、声乐、音乐和说话类别，结合分数过滤纯音乐与说话，合并候选并保留前后语境。分数不是准确率，仍可能误报或漏检；边界是粗略候选，需要试听。长视频按三分钟分段处理，每段保留前后重叠；已取消原先两小时的整片限制。原内容选片的最短时长和质量过滤仍然有效。

检测发生在规划和选片之前。时间区间进入真实模型提示和分析专用字幕行；即使 ASR 没有转写出歌词，也可据音轨候选进行选片。分析标记存放在 `metadata/analysis-only/`，不会作为可烧录的歌词字幕。句子边界精修不会依据残缺转写缩掉已选歌声范围。系统不自动生成歌词或猜测歌名。

模型未就绪或检测失败会说明状态并沿用字幕和制作要求；关闭检测会停用本项目的旧音频提示。缓存校验原视频大小、修改时间、模型和分段算法，换素材或模型不复用旧检测。每段结果保存到 `metadata/audio-chunks/singing/`，失败或暂停后重试复用完整分段；损坏分段会重跑。原视频时间轴合并候选，设置每段超时，内存不随整片音频时长增加。自动处理显示进度，可点击“暂停处理”。

## 存储和兼容性

- 本机数据目录的 `creator-library.json` 保存角色、词条和反馈；每次保存带修订号校验，并保留前一版 `creator-library.backup.json`。冲突提示重新打开，损坏文件保留原件，不覆盖为空库。
- 上限为 100 个角色、200 个词条、200 条反馈。每次上下文按匹配角色筛选并限制长度；不同项目的上下文隔离。
- 项目的 `metadata/singing-analysis.json` 保存歌声候选。权重存放在现有本地运行时的 `models/singing-ast/`。
- 空词库、不填角色名、不启用歌声检测时保持原路径。没有数据库迁移，不改供应商和原有媒体；时间线缓存区分制作要求、背景、人工档案、反馈和音频候选，旧缓存文件保留。
